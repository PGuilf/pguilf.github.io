Using MD files to document projects, LLM friendly

Back to Journal

Confluence is fine. But it's slow to update, rarely read, and by the time a project wraps up, half the decisions aren't in there anyway.

I've been experimenting with a different approach, documenting projects in markdown files, kept up to date throughout, and used as a direct input to AI tools.

The basic idea: Every major AI tool, Claude, ChatGPT, Langdock, NotebookLM, can read an MD file. That means your documentation isn't just a record, it's something you and your team can actually query through an LLM, through chat.

How I structured it: The file starts at kick-off, seeded with the brief and any existing Confluence context and description of stakeholders (linked to a separate stakeholder MD file). It grows with the project, stakeholder input, design decisions, user testing insights, feedback from content or engineering, links to video walkthroughs and vibe-coded explorations. Less about writing everything up perfectly, more about keeping it current. I update it using Claude and Whisper as I go, which keeps it efficient. I can also link it to Granola (AI meeting notes).

What it replaces: Previously I'd spread meeting notes and process steps across multiple Confluence pages. Now it's one file. Instead of hunting through pages or asking someone to recap a decision, you just upload it and ask. "What were the main constraints?" or "What did the content team flag?" The answer comes back with context.

Where it lives: I now attach it for sign off so team members can use it in Claude Projects, Langdock, ChatGPT or NotebookLM. The format isn't locked to any tool, which is the point.


The honest bit: It only works if you keep it updated. A stale MD file is as useless as a stale Confluence page. But the bar is lower, a few lines after a meeting, a paste from a transcript. More likely to actually happen.
