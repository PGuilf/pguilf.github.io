## Process
I start with discovery — understanding users, the business problem, and constraints before touching a design tool. I run workshops with stakeholders, analyse existing data, and use research to define the right problem before solving it. I work iteratively, validating decisions through user testing and collaborating closely with engineers to make sure designs actually ship.

Collaborative working is core to how I operate. I genuinely enjoy running workshops — getting a cross-functional team in a room (or a Miro board) to sketch ideas, align on problems, and move fast together. Sketching and whiteboarding are still a big part of how I think through problems early. That hasn't changed with AI.

What has changed is the low-fidelity stage. Vibe coding with tools like Claude Code means I can go straight from a sketch or idea to a working interactive prototype in the browser — skipping static lo-fi wireframes entirely. This speeds up validation significantly and produces something engineers can actually react to rather than interpret. It's changed the shape of my process: less time in grey-box wireframes, more time in real, testable code. I've written about this workflow in my AI journal.

On the research side, I use AI tooling for usability testing — running moderated and unmoderated sessions with AI-assisted synthesis to surface themes and patterns faster. This doesn't replace judgement; it removes the grunt work of tagging and clustering so I can spend more time on insight and decision-making. I also run diary studies for longer-horizon research — particularly useful for understanding habitual behaviours, emotional responses over time, and use cases that don't surface in a single session. Diary studies have been especially valuable on health and finance products where context and frequency of use matter.
